## Setup (the tooling)

1. **Install dependencies** - this creates `node_modules/` from `package.json`:

   ```bash
   npm install
   ```

   That pulls Vite (the dev server / bundler) and `canvas-confetti` (a tiny library for the win animation).

2. **Move your images into `public/`.** Vite serves everything in `public/` at the site root, in dev and in the build:

   ```bash
   mkdir -p public/images
   mv images/* public/images/ && rmdir images
   ```

   Then reference them with a leading slash: `/images/logo.gif`, `/images/undo.png`.

3. **Edit `index.html`** - the board is generated by JavaScript now, so empty the two tables, link the script, and fix the logo path:

   ```html
   <head>
     …
     <link rel="stylesheet" href="styles/sudoku.css" />
     <script type="module" src="scripts/sudoku.js"></script>
   </head>
   …
   <a class="brand" href="index.html">
     <img src="/images/logo.gif" alt="" />
     Sudoku Centre
   </a>
   …
   <main>
     <h1>Play Sudoku</h1>
     <!-- generated by sudoku.js -->
     <table id="board" aria-label="Sudoku board"></table>
     <table id="palette" class="palette" aria-label="Number palette"></table>
   </main>
   ```

4. **Edit `high_scores.html`** - give the table body an `id`, empty it, link the script, fix the logo path:

   ```html
   <head>
     …
     <script type="module" src="scripts/high_scores.js"></script>
   </head>
   …
   <table class="scores">
     <thead>
       <tr><th scope="col">Date</th><th scope="col">Duration</th></tr>
     </thead>
     <tbody id="scores-body"></tbody>
   </table>
   ```

5. **Run the dev server** and leave it open - it reloads as you save:

   ```bash
   npm run dev
   ```

## Requirements - implement `scripts/sudoku.js`

The state, the element references, and the scoring/celebration helpers are done. Fill in the six functions marked `TODO`:

1. **`renderBoard()`** - build 9 rows of 9 `<td>` from `board`. Give each cell `id="cell-r-c"`, show the digit (`getCell`) or `''` for `EMPTY`, add class **`user-input`** to cells the player filled (empty in `SAMPLE_BOARD` but not now), and a **click** handler calling `placeAt(r, c)`. End by calling `highlightConflicts()`.
2. **`highlightConflicts()`** - toggle the **`error`** class on each cell, based on whether `findConflicts(board, r, c)` is non-empty.
3. **`renderPalette()`** - a row of digits **1–9** (click → `selectDigit`) plus a final cell with `<img src="/images/undo.png" alt="Undo">` (click → `undo`).
4. **`selectDigit(digit)`** - remember it and mark its palette cell **`active`**.
5. **`placeAt(row, col)`** - ignore if no digit is selected or the cell is a **given clue**; otherwise push the current board onto `history`, `setCell` the new value, re-render, and `celebrate()` if `isComplete`.
6. **`undo()`** - pop the last board off `history` and re-render.

> **Where undo comes from:** because `setCell` returns a new board (your Lab 04 work), you can keep every previous board in `history` and step back - no special "undo" logic needed.

## Quality bar (this is graded)

- **Playable:** select a digit, click an empty cell to place it; conflicting digits turn red; undo steps back; filling the board correctly triggers the win (confetti + alert).
- **Given clues are protected** - you can't overwrite a starting number.
- **Scores persist:** finishing a game saves to `localStorage`, and the High Scores page shows them (newest data, fastest-first), formatted by your model functions.
- **Builds cleanly:** `npm run build` succeeds and `npm run preview` works, images and all.
- **Model tests still pass:** `npm test`.

## Reflection (include a short note in the repo)

Keeping the `<td>`s in sync with the `board` array by hand - clearing and rebuilding on every move - is tedious and easy to get wrong. That is why component frameworks exist. Next phase: React does this syncing for you.

## How you're graded

- **By rubric:** the game is playable (place / conflict / undo / win), scores persist and render, and the app builds.
- **Automated:** `node --test` still passes your model.
